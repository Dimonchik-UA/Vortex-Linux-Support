# Staging Folder

Some games require mods to be deployed from a **staging folder on the same filesystem volume** as the game itself. Under Proton `Z:` maps to `/`, so a game in your home directory and a game on an SD card can both appear as `Z:` even though they are different volumes. If staging is on the wrong volume, Vortex may report **"Mods can't be deployed."**

OVLS helps by offering to move your staging folder to the correct location.

## What is staging?

When you download a mod in Vortex, it is first unpacked into a staging folder. Vortex then deploys the mod files from staging into the game's folder. For some games (such as Cyberpunk 2077), mods can only be deployed if staging and the game are on the same volume, not merely on the same Wine drive letter.

## How OVLS helps

When Vortex reports a deployment failure, the staging folder is empty, and `host.json` provides a target on the game's volume, the extension shows a **"Move staging folder"** button in its notification. There is no separate manual "request fix" path. Clicking it:

1. Creates a new staging folder on the game's volume.
2. Updates Vortex's staging setting to point to the new location.

OVLS never moves an existing non-empty staging folder. The button appears only for the deployment-failure notification (`test-valid-activator`), with empty staging and a valid target from `host.json`.

## Staging folder location

`host.json` is generated by the installer next to the Extension:

- **v1** contains only `modsRoot` (the home staging root). The original same-drive check is kept for compatibility.
- **v2** also contains `volumes`, built from the real Steam libraries in `libraryfolders.vdf`. Each entry has an `anchor` (a Windows path to the volume root) and its own `modsRoot`:
  - a library inside your home directory keeps `~/Vortex Mods` only when the library and home are confirmed to be on the same filesystem;
  - a library on another filesystem — including a nested catalog such as `SD/Games/SteamLibrary` or a separate filesystem mounted under home — uses the mount point reported by Linux `findmnt` as the anchor, with `<mount point>/Vortex Mods` as the target. `library_path.parent` is never assumed to be the volume root.

The Extension selects the longest matching anchor for the game path, with a strict directory boundary and case-insensitive comparison. If `volumes` is present but invalid, or no anchor matches the game, OVLS offers no fix instead of guessing a location. Such damage is reported as `invalid host.json` in `vortex.log` rather than being mistaken for a "same drive" case. If a registered library is temporarily unavailable (for example an unmounted SD card), its previously generated volume is kept only while it is still present in `libraryfolders.vdf`; if the registration is removed, the volume is dropped and `verify` reports the change.

`verify` reports the number of damaged saved entries as `host_map_issues`. A valid entry must have `modsRoot` equal to `<anchor>\Vortex Mods`; entries with a different path are counted as damaged and are not reused. Install / Update repairs the map only when it can be rebuilt from the available Steam libraries; a damaged v2 map is never silently written back as v1. If the Steam root is unavailable but the installed v2 map is fully valid, the map is reused byte-for-byte and `verify` stays OK. If rebuilding is impossible because the map is damaged, the state is `host_map_unrepairable` and the installed file is left unchanged (see [Diagnostics](diagnostics.md)).

## Limitations

- OVLS does not move an existing non-empty staging folder. The move is offered only when Vortex reports the `test-valid-activator` deployment failure, staging is empty, and `host.json` provides a valid target; there is no manual trigger for this button.
- SD-card staging targets are generated from the real Steam libraries; an automatic staging move on a real SD card still needs verification on SteamOS.
- SteamOS Game Mode has not been tested. R2/L2 triggers work via SteamOS input handling; other controller interactions with Vortex UI elements have not been fully tested.

## Troubleshooting staging

If Vortex reports **"Mods can't be deployed."**:

1. Check where your game is installed (home directory or an additional Steam library volume).
2. Open Vortex and look for the OVLS notification offering to move the staging folder.
3. Click **Move staging folder**.
4. Restart Vortex if needed and try deploying mods again.

If no notification appears, staging may be non-empty, `host.json` may be v1, or the game volume may not be in the generated `volumes` map. Otherwise ensure the game and staging folders are on the same volume and that the staging folder is writable.
